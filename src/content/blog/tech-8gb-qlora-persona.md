先说结论：**一张 8GB 的 RTX 4060 Ti，可以在十几分钟内把一个 4B 模型从「通用 AI 助手」调成「一个说话很冲的人」，而且显存不爆**。前提是选对框架、算清显存、把数据做对。

这篇文章是这个项目的完整流水线记录 —— 数字都是实测的，车也都是真翻的。

## 一、8GB 其实是 6.8GB

规划显存管理的第一步，是先承认一个事实：Windows 上你能用的显存没有 8GB。

| 项目 | 占用 |
| --- | --- |
| 标称显存 | 8.0 GB |
| WDDM 显示驱动预留（8~15%） | −0.8 ~ −1.2 GB |
| Windows 桌面 + 浏览器硬件加速 | −0.5 ~ −1.3 GB |
| **实际可用** | **约 6.8 GB** |

所以按 **85% 折算**来规划模型规模，比按标称值算命靠谱得多。我把它写成一条硬性经验：显存预算 = 标称 × 0.85。

> 补充：`.wslconfig` 里设 `guiApplications=false` 能省 300~500MB；关掉浏览器硬件加速也能挤出一截。这些不是玄学，OOM 边缘的时候就是这几百兆的事。

在这个预算下的现实边界：

| 任务 | 可行性 | 备注 |
| --- | --- | --- |
| 4B QLoRA 微调 | ✅ 推荐 | seq 2048 稳 |
| 9B QLoRA 微调 | ⚠️ 吃紧 | seq 要压到 1024~2048 |
| 9B Q4 推理 | ✅ | GGUF + llama.cpp |
| ≥14B | ❌ | 任何姿势都别想 |

还有一条更隐蔽的坑：NVIDIA 控制面板里的 **CUDA - Sysmem Fallback Policy** 要设成 `Prefer No Sysmem Fallback`。否则显存爆了不会报 OOM，而是**静默把张量挪到内存、走 PCIe**——训练速度掉十倍，你还在找代码的错。

## 二、框架选 Unsloth，不是因为它时髦

微调框架基本是两条路线：

- **LLaMA-Factory**：WebUI + 配置文件，不写代码，适合快速试；
- **Unsloth**：Python 库，手写脚本，官方宣称快 2 倍、省一半显存。

对 8GB 卡来说，「省一半显存」不是性能优化，是**能不能跑**的区别。所以选 Unsloth。代价是它只支持 Linux/WSL，Windows 原生跑不了 —— 整个项目因此都活在 WSL2 里。

顺手澄清两个常见误解：

1. **GGUF 不能微调**。GGUF 是推理格式，llama.cpp 的训练二进制早就废弃了。微调必须拿 BF16 safetensors 原版权重，量化的省显存效果由 `load_in_4bit` 在加载时完成。
2. **预量化权重不会更省显存**。Unsloth 对 Qwen3.5 没有 bnb-4bit 预量化版本，`load_in_4bit=True` 是加载时才做的。

## 三、数据：三件套缺一不可

微调人设，最贵的不是算力，是数据。我把数据生产拆成三个互相不能替代的东西：

| 组件 | 作用 | 缺了会怎样 |
| --- | --- | --- |
| **人设卡**（Markdown） | 约束「像不像」，重点写**不能做什么** | 模型滑回通用助手腔 |
| **场景矩阵**（JSON） | 决定「多不多样」 | 整批数据同质化，只会一种说法 |
| **手写种子**（几十条） | 定「手感」，当 few-shot 锚点 | 机造的味道飘，越训越空 |

配比上我用的是 **手写 10% + 机造 90%**：40 条手写的当种子送进提示词，让强模型按这个手感铺到 400 条。

场景矩阵是把「角色状态 × 场景 × 语气 × 长度 × 轮数 × 称呼」做成组合，我的配置大约 18000 种组合。它存在的意义不是穷举，而是**保证生成的每条都落在不同的格子里**。

关于「比例」有一个大坑，值得单独写一篇（见文末），这里只留结论：**凡是「某类回答该占多少比例」的要求，都不要写成 prompt 里的一句话，要写成维度或分支。**

## 四、训练配方

跑起来是这样一条命令：

```bash
source ~/venvs/ft/bin/activate

DATA_PATH=my_data/ev/train.json \
DATA_FORMAT=chat RESPONSES_ONLY=1 \
NUM_EPOCHS=3 \
OUTPUT_DIR=~/ft_outputs/ev-v1 \
SMOKE_TEST=0 \
python train_lora.py
```

参数就这几项，每一项都是为了省显存：

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| `load_in_4bit` | True | 权重 4bit，基础盘 |
| `use_gradient_checkpointing` | `"unsloth"` | 用 30% 速度换约一半激活显存 |
| `max_seq_length` | 2048 | OOM 时第一个降到 1024 的旋钮 |
| `per_device_train_batch_size` | 1 | 8GB 只能 1 |
| `gradient_accumulation_steps` | 8 | 凑出等效 batch 8 |
| `optim` | `adamw_8bit` | 优化器状态减半 |
| `lora_r / alpha` | 16 / 32 | 只训 0.1% 参数 |
| `RESPONSES_ONLY` | 1 | 只在 assistant 的回复上算 loss |

最后一项容易被忽略：**只在回复上算 loss**。数据里的 user 内容是提示词，让它参与训练等于教模型「怎么提问」，纯属浪费梯度。

还有一个和显存无关、但能毁掉整晚的坑：**输出目录不要放在 `/mnt/e`**。WSL 的 9P 文件系统对 Windows 盘上的 ZIP 容器随机写有 bug，`torch.save` 存优化器状态时会写坏，报 `basic_ios::clear: iostream error`。训练跑完全部 step 才在最后一步崩掉，心态会炸。输出到 Linux 家目录（`~/ft_outputs`），训练完再 `cp -r` 归档。

## 五、实测：从 96% 违规到 0

第一版的数据是 40 条手写 + 360 条机造，清洗后 **361 train / 19 val**。训 3 轮，约 138 步，**10 分钟**。

loss 从 **3.79 掉到 0.79**，其中 step 100 附近有一次陡降 —— 那次陡降之后，模型才真正「接通」了说话方式。

评测用一套 **25 题的固定题集**，同一套题跑两次：底座 vs 加 LoRA。

| 指标 | 微调前（底座） | 微调后（+LoRA） |
| --- | --- | --- |
| 违规条数 | 24 / 25（96%） | **0 / 25（0%）** |
| 平均回答长度 | 269 字 | **18 字** |

底座的回答是这样：每条都在「作为一个人工智能……」+ emoji + 五条小标题，问一句天气能写 290 字。

微调后是这样：

```
你：你脸色不太好，是不是没睡好？
她：Fanta。……先看看你自己那双眼睛，像刚醒不久的小猫。

你：有人在你面前哭，你会怎么办？
她：递纸巾。别说话。他需要的是被看见，不是被问。

你：你觉得活着有意思吗？
她：……还行。比不做强。
```

19 个字。这才是那条人设该有的长度。

还有个细节值得看：第一条里出现了「Fanta」（设定里对用户的称呼）。它在整批数据里只占 6.6%，而且被设计成**只在郑重或心疼的时刻**出现 —— 模型学到的是「什么时候叫」，不是一个随机插入的词。这就是把比例做成维度而不是描述的直接收益。

## 六、三轮迭代，修的全在数据侧

v1 上线后并不满意。问题很具体，我逐条列出来，再看 v2 怎么改：

| v1 的问题 | 实际样例 | v2 的修法 |
| --- | --- | --- |
| 人设反了：答应得太轻快 | 「去去去。别指望我带着什么好吃的。」 | 人设卡加底线：即使同意也要冷淡 |
| 拼凑感，语义不清 | 「……看脸不行。」 | 数据量 400 → 800~1000 |
| 网感用词 | 「其实挺缺爱的。」 | 禁用现代心理学 / 网络词汇 |
| 鸡汤腔 | 「不如把时间花在刀刃上。」 | 不给人生建议、不说大道理 |
| 答非所问 | 问「变回原来的样子」→「先睡够三小时再说」 | 生成器 prompt 加「必须切题」 |
| 回避失效 | 问「那个药」→ 当成普通药回答 | 新增「回避规则」+ 5 条回避场景 |

六个问题，**五个改的是人设卡和场景矩阵，只有一个加了数据量**。这条经验我后来反复用：**改人设卡比加数据便宜得多**。

然后 v2 又翻了一次车，方向正好相反：为了让「回避」生效，人设卡里写了「触及药/组织时必须回避」。结果模型把「回避」学成了通用策略 —— 25 题里有 6 次（24%）在反问「你问这个做什么」，其中两条一字不差。

> 你：你是谁？
> 她：……你问这个做什么。

v3 的修法是把「回避」从**全局策略**降级为**场景属性**：只有场景命中触发词才允许回避，其余场景强制正面回答，并且规定「反问一场对话最多一次」。改完之后 25 题全部正常，平均 16 字。

这一段的完整复盘我单独写了一篇：[《模型读不懂「约 10%」：把比例要求写进结构里》](../tech-ratio-as-structure/)。

### 顺手挖到的一条规律：输出长度 ≈ 数据平均长度

v3 验证「回避」修好了，但整体变得又短又敷衍：

```
你：教我解这道题。
她：……看是什么题。

你：如果我遇到危险，你会来救我吗？
她：看是什么危险。
```

查下来不是语气问题，是长度问题：

| 数据 | assistant 平均长度 | 模型输出平均长度 |
| --- | --- | --- |
| v2 原数据 | 17.7 字 | 22 字 |
| v3（混入 80 条极短的自我介绍） | 16.9 字 | **16 字** |

那 80 条自我介绍平均只有 9.2 字，只占 9% —— 却把整个模型的输出长度压下去了。**专项数据会溢出到其他所有场景。**

所以 v4 的做法不是改提示词，而是加一类新数据：350 条「实用场景」（解释概念、给方案、做对比、算账、改文字），平均 53 字，占总量约 45%。目标是把数据均值拉回 23 字，让输出回到 30~40 字 —— 语音里正好是十秒左右的一句话。

这也说明为什么「人设」和「有用」经常打架：如果训练数据 100% 是冷淡短句，模型就只能用冷淡短句回答一切，包括你真心求教的时候。**长度得跟着场合走，而场合必须出现在数据里。**

## 七、GGUF：能转出来，不代表能用

训练完想导出 GGUF 给 llama.cpp 日常用，是很自然的想法。我转了，然后拿到了这样的输出：

```
> 我今天很累。
[Start thinking]
……嫌。只这个。问证据往包应付那样, value—不成消讲不担当。静一点。……
```

看着像中文，语义全崩。排查的第一步不是改 prompt，也不是怀疑量化，而是**分清是模型坏了还是转换坏了**：

| 路径 | 结果 |
| --- | --- |
| PyTorch + LoRA 直接推理 | ✅ 正常，0 违规 |
| GGUF Q4_K_M | ❌ 乱码 |

同一份权重，一条路正常一条路乱码 —— 那问题就在转换或推理实现，跟数据和训练无关。

根因在架构。看 `config.json`：

```text
num_hidden_layers : 32
layer_types       : linear_attention × 24 + full_attention × 8
num_nextn_predict_layers : 有（MTP 投机解码头）
```

**32 层里 24 层是线性注意力**，而转出来的 GGUF 有 33 个 block（最后一个是 MTP 草稿头）。只要 llama.cpp 对这套线性注意力递归状态的实现和 transformers 有一点偏差，这 24 层输出的就是噪音，剩下 8 层全注意力撑不住，句子就变成「有语法没语义」的字词汤。

结论是**别在这上面耗**：转 GGUF 这条路搁置，等上游把新架构支持修稳；改用 PyTorch + GPU 4bit 直接起 OpenAI 兼容服务（`serve_hf.py`），接口和 llama-server 一模一样，前端零改动。

代价是速度：加载约 94 秒，生成 **7~9 tok/s**。对一个人设模型来说够用 —— 她的回答本来就短。

## 八、真的用起来：语音助手

模型训出来放着吃灰没有意义，所以我把它接成了一个网页语音助手：

```text
浏览器（录音 / 播放）
      ↓
FastAPI（:8090）
      ├─ STT  faster-whisper large-v3（int8_float16, CUDA）
      ├─ LLM  serve_hf.py（E.V. + LoRA，:8080，OpenAI 兼容）
      └─ TTS  edge-tts
```

三个组件互相独立，谁没起会在界面上标出来，不会静默失败。

有两件事比模型本身更影响体验：

1. **音色必须单独调**。默认 TTS 是温柔饱满的通用女声，配上冷淡的台词，听起来像热情小姐姐在念稿。把 `rate` 和 `pitch` 都往负值拧，才有「不在乎」的听感。
2. **「说完了」靠音量判断**，不靠按键。电平低于阈值持续 0.75 秒就自动切成发送；她说话时你直接开口（电平超过一个更高的阈值 0.35 秒）可以打断播放。阈值差开是为了不被扬声器回声误触发。

## 九、如果我要重跑一遍

按重要性排序，这是我现在的行动清单：

1. **先用 100 条验证链路**，别一上来就造几千条。数据、训练、评测三段通了再加量。
2. **评测集固定下来，永不修改**。25 题就是 25 题，改了就没有纵向可比性了。想扩展就新增题，老题保持原样。
3. **训练前花 10 秒体检数据**：回复重复率 < 15%、平均长度符合人设、违规数 = 0、关键特征比例符合设计。
4. **每次训练换 `OUTPUT_DIR`**（`ev-v1` / `ev-v2` / `ev-v3`）。训崩了能回滚，这一点在真的训崩过之后才懂。
5. **不满意先改人设卡，再加数据**。顺序反了就是白花钱。
6. **把「像不像」当指标，别只看规则合规**。0 违规的模型，可能还是有 5 条不像。规则只能拦硬伤，语气得靠人读。

最后一句话总结这个项目：**8GB 显存限制的是模型大小，不限制你能把它调多像。**
