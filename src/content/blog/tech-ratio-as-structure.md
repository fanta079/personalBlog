做数据生成时，我遇到过两次结论完全相反、根因完全相同的翻车。

第一次：想要「偶尔叫一声对方的名字」，于是在人设卡里写「大约每 10 条回答里有 1 条会叫」。生成 240 条，**叫名字的 0 条**。

第二次：想让模型「避开某些不该谈的话题」，于是写「触及这些话题时**必须**回避」。生成 800 条，训出来之后 25 道评测题里有 **6 次**在反问「你问这个做什么」，其中两条一字不差。

一个是「太弱、完全不生效」，一个是「太强、泛化成万能句」。它们不是两个 bug，是同一个设计错误的两面。

## 第一次：把「稀有」写成了「不用」

人设卡里原本是这么写的：

> 默认只用「你」。大约每 10 条回答里有 1 条会叫「Fanta」—— 全是就廉价了，一条不叫又失去了那份分量。

这句话对人来说是清楚的，对模型不是。它抓到的是「稀有」这个模糊概念，而「稀有」在生成时最省力的执行方式是：**不写**。

实测 240 条，0 条叫名字。不是「少了点」，是干净利落的零。

修法不是把话说重一点（「一定要偶尔叫」），而是**把比例从描述变成结构**：

```json
"call_names": [
  "只用「你」，不叫名字",
  "只用「你」，不叫名字",
  "只用「你」，不叫名字",
  "必须叫一次名字「Fanta」（郑重 / 心疼 / 生气的时刻）"
]
```

这是一个场景维度，取值按 9:1 排布。生成器每次从维度里抽一个值，抽到哪条就执行哪条。比例由**抽样结构**保证，不依赖模型理解「10%」是什么意思。

改完的统计：叫名字占比 **6.6%**，和设计值一致。

## 第二次：同一句「必须」，变成了万能句

后来发现模型对某些话题不设防，于是我在人设卡里加了一段：

> 触及「药」「组织」相关话题时，**必须**回避，不要正面回答。

规则本身没错，效果也很直接 —— 回避是学会了。但学过头了。

上线实测：

```
你：你是谁？
她：……你问这个做什么。

你：我是谁
她：……你问这个，是想让我答，还是想让我问。
```

问「你是谁」这种最基础的身份问题，她也在躲。25 题固定评测里，「你问这个做什么」出现 **6 次（24%）**，其中第 1 题和第 5 题的回答**一字不差**。

一字不差是关键信号：这不是「语气相似」，是**同一段模板被反复调用**。模型把「回避」学成了一个通用应答策略，装在了所有「关于她自己」的问题上。

## 根因：模型执行的是「场景 → 策略」，不是「程度」

两次翻车放在一起看，规律非常清楚：

| 版本 | 写法 | 实际结果 |
| --- | --- | --- |
| v1 | 「**大约每 10 条**会叫一次名字」 | 太弱 → 生成 **0 条** |
| v2 | 「触及这些话题时**必须**回避」 | 太强 → 泛化成 **万能句** |

模型不理解「大约」「偶尔」「有时」这类程度副词 —— 它们没有可执行的语义，只有「往少」或「往多」的方向暗示。而一旦某个规则被写成一个没有边界条件的强指令，「必须」就会**溢出到所有相邻场景**，因为模型不知道边界在哪。

它真正能稳定执行的，是这种形式：

> 这个场景 → 这个策略。别的场景 → 别的策略。

## 修法：三层，全在配置里

v3 我没改代码逻辑，只改了三处配置。

### 1. 给规则划出边界，并给正误对照

人设卡里把「回避」从全局策略改成白名单触发，同时把一个最容易误伤的场景明确写死：

> 被问「你是谁」时直接回答，不许回避。
>
> ❌ 「你问这个做什么。」
> ✅ 「E.V.。……就这么叫我。」

正误对照比形容词有效得多。写「要直接一些」模型没概念，给两句对照它立刻知道差在哪。

### 2. 场景矩阵补上被漏掉的场景

原来矩阵里没有「身份自述」这类场景，所以「你是谁」落到的是最接近的「被追问过去」格子 —— 那格里写着回避。

补了两条场景（「你是谁」「我是谁」），并标注**必须直接答**。这是纯覆盖问题：没设计过的场景，模型只能拿最像的那条去套。

### 3. 让回答策略跟场景强绑定

第三层是在抽样逻辑里做的分支：

```python
if hit_trigger_words(scene):
    strategy = "可以回避或反问"
else:
    strategy = "正面回答，不许回避"
```

这一步的关键不是分了两支，而是**每一支都能对自己的场景负责**。如果随手改成「80% 正面回答」，就会出现最糟的情况：抽到「那个药」这种必须回避的场景，任务书却要求「正面回答」——**自相矛盾的任务书，比没规则更坏**。

改完的检查项：

| 指标 | 值 |
| --- | --- |
| 场景数 | 33 → 36 |
| 触及敏感话题占比 | 13.8% |
| 策略与场景配对错误 | **0** |

## 可以迁移到哪里

这条经验不只适用于造人设数据。凡是出现「占比」「频率」「多数情况下」的需求，都该问一句：**这句话能不能变成一个字段？**

| 需求 | 别写成 | 写成 |
| --- | --- | --- |
| 客服偶尔主动推荐 | 「适时推荐相关产品」 | 场景维度：`推荐` / `不推荐`，按比例抽样 |
| 拒答率控制在 15% | 「大部分问题要正常回答，少数拒答」 | 每类问题绑定固定策略，再统计 |
| 回答长度有长有短 | 「长度适中，偶尔详细」 | 长度作为独立维度，短 / 中 / 长各占一档 |
| 错误提示要友好 | 「友好地提示错误」 | 直接给 3 条正确示例 + 3 条错误示例 |

## 一句话版本

**模糊的强度描述不可控，必须落到结构上。** 模型不会按你心里的比例生成，它只会按你给的结构生成。
