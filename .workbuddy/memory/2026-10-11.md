## 关键踩坑（务必记住）

1. **Astro 的 `base` 不会自动给 `<a href>` 加前缀**（实测 v5.18.2 只对 `Astro.url` 生效）。必须用带尾斜杠的 `BASE` 常量（取自 `import.meta.env.BASE_URL`）手工拼接所有内部链接与静态资源，否则 GitHub Pages 子路径下全部 404。
2. `actions/configure-pages` 的 `enablement: true` 会失败：`Resource not accessible by integration`（workflow 的 GITHUB_TOKEN 无权创建 Pages 站点）。首次开启用：`gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow`，或到 Settings → Pages 手动选 GitHub Actions。开启后工作流里不要再带 `enablement: true`。
3. 本机沙箱无法访问 github.com，且 esbuild 后安装脚本报 `EBUSY` —— `npm install` / `npm run build` 必须在非沙箱（dangerouslyDisableSandbox）下执行。
4. 本机 GCM（`helper-selector`）推送会卡住不返回。用 gh 凭据助手推送成功：
   `git -c credential.helper= -c credential.helper='!gh auth git-credential' push origin main`
   （gh 已登录 `fanta079`，token scope 含 `repo` + `workflow`）
